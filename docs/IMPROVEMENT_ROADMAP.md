# مرجع تحديث ورفع كفاءة النظام

**آخر مراجعة:** 2026-10-31  
**الغرض:** خارطة عمل مقترحة مبنية على التنفيذ الحالي في [مرجع تحليل النظام](SYSTEM_ANALYSIS.md). الأولويات مقترحات تحتاج اعتمادًا تجاريًا قبل تغيير معنى الأرقام.

## مبادئ التنفيذ

- حماية صحة البيانات وتعريف المؤشر قبل تحسين شكل اللوحة.
- جعل الاستيراد قابلًا للتراجع/الاستعادة، وعدم إسقاط البيانات بصمت.
- تغطية القواعد باختبارات صغيرة قبل إعادة الهيكلة أو تحسين الأداء.
- تقسيم التنفيذ إلى تغييرات صغيرة، وتحديث `PROJECT_STATUS.md` في كل تغيير.
- تجنب ترحيل البيانات أو تغيير دلالات التكرار والتاريخ دون خطة توافق ونسخة احتياطية.

## الأولوية 0: حسم الدلالات وحماية البيانات

1. **تعريف الشحنة الفريدة والتكرارات:** اتفقوا هل السجل هو شحنة في تقرير يومي أم رقم تتبع فريد على نطاق زمني. وثّقوا سلوك ظهور الرقم في أيام مختلفة، ثم اجعلوا اسم بطاقة KPI متوافقًا مع التعريف.
2. **تثبيت مصدر التاريخ:** قرروا ترتيبًا صريحًا بين تاريخ الصف وتاريخ اسم الملف والتاريخ اليدوي. نفّذوا الاختيار بالكامل أو أزيلوا خيار ربط عمود `Date` غير الفعال من الواجهة.
3. **التحقق من التاريخ:** تحققوا من صلاحية التاريخ التقويمية، واعرضوا خطأ/تأكيدًا بدل ملء تاريخ اليوم بصمت عند فشل الاستخراج.
4. **تحديد سياسة استبدال الملفات:** الاسم الحالي هو مفتاح الملف. أضيفوا تأكيدًا واضحًا للاستبدال، وفكروا في بصمة المحتوى أو مفتاح داخلي ثابت إذا كان المطلوب تمييز إعادة تسمية الملف عن استبداله.
5. **قوة مفاتيح السجلات:** استبدلوا تركيب المفتاح النصي غير المهيكل بمفتاح مركب أو ترميز غير ملتبس لمعرف الملف ورقم التتبع.

**معايير القبول:** لا يقبل تاريخ غير صالح؛ تعرض الواجهة سياسة التكرار والاستبدال بدقة؛ لا يتغير إجمالي الشحنات دون قرار موثق؛ ويمكن استيراد الملف ثم استبداله دون سجلات يتيمة.

## الأولوية 1: جودة البيانات والاعتمادية

- أضيفوا اختبارات للوحدات الحرجة: صيغ التاريخ، اكتشاف الصف/العمود، القيم الفارغة، التكرارات، المرشحات، وحسابات المؤشرات والحالات الصفرية.
- أضيفوا ملفات Excel اصطناعية صغيرة كعينات ثابتة، مع حالات أوراق متعددة وعناوين غير قياسية وملف تالف.
- أظهروا تقرير استيراد لكل ملف: صفوف مقروءة، سجلات مقبولة، تكرارات محذوفة، تتبع مفقود، أخطاء ربط، والأعمدة المكتشفة. لا تجعلوا تجاهل الصفوف غير الصالحة صامتًا.
- أضيفوا مخزن/إعدادات حفظ لعناوين الملفات المكتشفة، وأعيدوا بناء خيارات المابنج من الملفات المحفوظة بعد إعادة فتح الصفحة.
- حسّنوا التعامل مع أخطاء IndexedDB: رسائل واضحة عند امتلاء الحصة أو فشل المعاملة، وإتاحة إعادة المحاولة دون إظهار نجاح غير صحيح.
- راجعوا دورة حياة IndexedDB وترقيات المخطط: ترقيم الإصدارات، ترحيلات قابلة للتكرار، معالجة `versionchange`، واختبار ترقية نسخة قديمة.
- أضيفوا تصديرًا واستيرادًا لنسخة احتياطية محلية، مع إصدار مخطط وتحقق قبل استعادة البيانات.

**معايير القبول:** اختبارات المحلل والتحليلات تمر في CI؛ فشل الملف لا يفسد بيانات الملفات الأخرى؛ يمكن استعادة نسخة احتياطية؛ وترقية قاعدة قديمة تحفظ السجلات والإعدادات.

## الأولوية 2: الأداء عند نمو البيانات

- قيسوا زمن استيراد وعرض أحجام ممثلة، مثل 10 آلاف و100 ألف سجل، قبل اختيار التحسين.
- تجنبوا تحميل كامل قاعدة الشحنات ثم المرور عليها عدة مرات عند الأحجام الكبيرة؛ استخدموا فهارس IndexedDB وقراءة على دفعات أو تجميعًا داخل Worker عند الحاجة.
- افصلوا الحسابات الثقيلة عن إعادة العرض، مع إبقاء نتائج الفلاتر متسقة. لا تضيفوا تخزينًا مؤقتًا قبل اختبار بطلان الذاكرة عند تغيير البيانات والإعدادات.
- استخدموا عرضًا افتراضيًا لجدول المستكشف إذا أصبحت الصفوف كثيرة، وحدّوا عدد نقاط الرسوم دون تغيير نتائج المؤشرات.
- راقبوا حجم الحزمة. تحذير البناء الحالي يذكر أن حزمة JavaScript تتجاوز 500 kB؛ افحصوا التحميل الكسول/تقسيم المسارات واعتمادات الرسوم وExcel بدل رفع الحد فقط.

**معايير القبول:** حددوا ميزانية زمنية وحجم بيانات مستهدفًا مع فريق التشغيل، ثم سجلوا قياسًا قبل/بعد على جهاز مرجعي. لا تعتمدوا تحسينًا يغير نتيجة حسابية.

## الأولوية 3: قابلية الاستخدام والصيانة والنشر

- أضيفوا حالات تحميل وفشل وحفظ واضحة، ومنع إغلاق/تكرار عملية الرفع أثناء المعالجة.
- راجعوا إتاحة لوحة المفاتيح وتسميات عناصر التحكم والتركيز في القوائم والنوافذ المنبثقة، واختبروا العرض على الشاشات الصغيرة.
- وحّدوا رسائل الأخطاء والتأكيدات بدل `alert` و`confirm` عند تحسين تجربة الاستخدام.
- راجعوا الاعتمادات المباشرة وغير المستخدمة، وبالأخص `@google/genai` و`express` اللذين لا يظهر لهما استخدام مباشر في `src/` وقت المراجعة. لا تحذفوا اعتمادًا قبل التحقق من إعدادات البناء والنشر.
- عالجوا تحذيرات البناء ذات الأولوية: استخدام `__dirname` في إعداد Vite، وحجم الحزمة، ثم حددوا سياسة متابعة نتائج `npm audit` مع تحديثات واعية بالتوافق.
- أضيفوا CI لتثبيت مقفل بـ`npm ci` ثم `npm run lint` و`npm run build` والاختبارات. وثّقوا بيئة النشر وسياسة الاحتفاظ بالبيانات.

**معايير القبول:** يستطيع مستخدم لوحة المفاتيح إتمام الرفع والفلاتر وإدارة الملفات؛ تعمل أوامر CI من تثبيت نظيف؛ وتُسجل نتائج تدقيق الاعتمادات والقرارات بدل إخفائها.

## تسلسل تنفيذ مقترح

1. اعتماد دلالات التاريخ والتكرار والاستبدال مع مالك بيانات التشغيل.
2. كتابة اختبارات للمحلل والتحليلات وتثبيت أمثلة Excel مصطنعة.
3. إصلاح صحة التاريخ والمابنج والمفاتيح وسياسة الاستبدال مع ترحيل متوافق عند الحاجة.
4. إضافة تصدير/استعادة وواجهات أخطاء استيراد وتخزين واضحة.
5. قياس الأداء على أحجام واقعية، ثم اختيار تحسينات محددة بناءً على القياس.
6. إكمال الإتاحة، مراجعة الاعتمادات والأمان، وإضافة CI ودليل النشر.

## بوابة كل تغيير

قبل الدمج: راجعوا تأثير التغيير على بيانات IndexedDB الحالية، أضيفوا/حدّثوا الاختبارات، نفذوا `npm run lint` و`npm run build` والاختبارات المتاحة، تحققوا من بقاء الاستيراد والتصفية وحذف الملف وتعديل التاريخ سليمة، ثم أضيفوا سطرًا إلى سجل [حالة المشروع](../PROJECT_STATUS.md). إذا لم ينطبق أحد الفحوص، اكتبوا السبب في سجل الحالة.
