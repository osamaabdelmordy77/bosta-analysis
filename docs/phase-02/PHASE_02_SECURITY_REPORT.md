# تقرير المرحلة 02 — المصادقة والتحكم في الوصول

**التاريخ:** 2026-11-03
**الحالة:** تقرير تاريخي للمرحلة 02. تكامل الواجهة والاستيراد اللاحق موثق في [تقرير MySQL للمرحلة 03](../phase-03/MYSQL_IMPORT_REPORT.md).
**النطاق وقت المرحلة 02:** مصادقة جلسات الويب، صلاحيات متعددة المؤسسات، إدارة العضويات والأدوار ومراكز التوزيع، وتدقيق أحداث الوصول. لم يبدأ تغيير واجهة React أو بناء واجهات الشحنات والتحليلات حينها.

## 1. ملخص التنفيذ

- أضيف Laravel Sanctum لمصادقة SPA باستخدام جلسات Cookie مع CSRF. أضيفت نقاط دخول وتسجيل خروج واستعادة كلمة المرور وعرض المستخدم والجلسات وإبطالها.
- أضيفت مصادقة صلاحيات قائمة على أدوار ثابتة ضمن المؤسسة، مع دور Super Admin عالمي مستقل يُسجل في سجل أحداث append-only على مستوى التطبيق.
- عُزلت طلبات المؤسسة عبر middleware وسياق مؤسسي scoped، وأُغلِق السياق دائمًا بعد الطلب. يُرفض تمرير معرّف مؤسسة من query أو body أو header، ويُتحقق من العضوية النشطة قبل تنفيذ عمليات المؤسسة.
- أضيفت سياسات للتحكم في المستخدمين والأدوار ومراكز التوزيع وسجلات التدقيق، مع إخفاء موارد المؤسسة غير المصرح بها برد 404.
- تُطبّق صلاحيات مركز التوزيع عند إرجاع قائمة المراكز وتفاصيلها؛ وأضيفت خدمة نطاق جاهزة لتطبيق النطاق نفسه على استعلامات الشحنات المستقبلية.
- أضيفت سجلات تدقيق للعضويات والأدوار وتكليف المراكز، وسجل أمني لا يحتفظ بكلمة المرور أو Cookie أو معرّف جلسة خام أو بيانات Excel.
- لا يوجد Redis أو Horizon كشرط. يبقى Queue driver المحلي على قاعدة البيانات، ولا يبدأ Worker ضمن المرحلة.

## 2. الواجهات المضافة

المسارات ضمن `/api`:

| المسار | الغرض |
|---|---|
| `POST auth/login` | تسجيل الدخول مع تحديد المعدل |
| `POST auth/logout` و`GET auth/user` | تسجيل الخروج وعرض المستخدم الحالي |
| `POST auth/forgot-password` و`POST auth/reset-password` | بدء واستكمال إعادة تعيين كلمة المرور مع تحديد المعدل ومنع كشف وجود البريد |
| `GET auth/sessions`، `DELETE auth/sessions/{reference}`، `DELETE auth/sessions/others` | إدارة جلسات المستخدم؛ المراجع المعروضة HMAC وليست معرفات جلسات قاعدة البيانات |
| `GET organizations` | المؤسسات المتاحة للمستخدم |
| `GET/POST organizations/{organization}/members` | عرض الأعضاء ودعوة/إنشاء عضو |
| `PATCH .../members/{user}/role` و`PATCH .../members/{user}/status` | تغيير الدور أو حالة العضو وفق السياسة |
| `PUT .../members/{user}/hubs` | إدارة وصول العضو إلى المراكز |
| `GET .../roles` و`GET .../permissions` | عرض كتالوج الدور والصلاحيات الثابت |
| `GET .../hubs` و`GET .../hubs/{hub}` | عرض المراكز ضمن نطاق وصول المستخدم |
| `GET .../audit-logs` | استعراض سجل المؤسسة مع ترشيح البيانات الوصفية المعادة |

تُسجل حزمة Sanctum مسار CSRF الخاص بها (`/sanctum/csrf-cookie`) منفصلًا عن 19 مسار API خاصًا بالتطبيق.

## 3. نموذج الأدوار والصلاحيات

الأدوار المؤسسية الثابتة: Organization Admin وData Manager وAnalyst وHub Manager وViewer وAuditor. الدور العالمي Super Admin منفصل عن عضوية المؤسسة، ولا يمنح تلقائيًا عضوية أو وصولًا إلى كل مؤسسة. لا توجد واجهة API لتعديل مصفوفة الصلاحيات.

تمنع القواعد خفض صلاحيات المستخدم لنفسه، وتقيّد تعيين الدور بحسب صلاحية المنفذ، وتحمي آخر Organization Admin نشط داخل المؤسسة وآخر Super Admin نشط على مستوى النظام. عمليات منح وإلغاء Super Admin وإعداد أول مؤسسة/مسؤول تتم بأوامر CLI صريحة ومدققة، لا عبر Endpoint عام.

## 4. الجلسات وحماية المصادقة

- تستعمل الجلسات مخزن قاعدة البيانات محليًا مع فهرس مركب للنشاط والمستخدم.
- أضيف middleware للتحقق من انتهاء الجلسة فعليًا قبل المصادقة؛ اكتُشف أن صف الجلسة المنتهي قد يبقى حتى جامع البيانات، لذلك لا يعتمد الرفض على التنظيف الدوري وحده.
- تضبط ملفات البيئة أمثلة أصلًا محليًا على منافذ الواجهة والخادم، Cookie من نوع host-only وHttpOnly وSameSite Lax، وتحديد المعدل لمحاولات الدخول وإعادة التعيين.
- يُرسل إشعار إعادة التعيين عبر إعداد Mail الافتراضي `array` لتفادي طباعة روابط الاستعادة في سجل محلي. يلزم إعداد SMTP آمن قبل تفعيل هذه الميزة لمستخدمين فعليين.

## 5. تغييرات البيانات

أضيفت هجرتان فقط للمرحلة 02: جدول سجل أحداث Super Admin، وفهرس جلسات مساعد. لم تتغير جداول بيانات Bosta أو Manifest الأعمدة الـ211 أو علاقات الشحنات والمحاولات من المرحلة 01. لا توجد Migrations لواجهة React أو بيانات Excel.

## 8. القيود والقرارات غير المحسومة

1. **البريد:** يجب إعداد SMTP/مزود رسائل إنتاجي، وتحديد سياسة انتهاء وإعادة إرسال رابط الاستعادة ومراقبة تسليم البريد قبل إتاحة كلمات المرور للمستخدمين.
2. **الأصول المنشورة:** أمثلة البيئة المحلية تسمح HTTP على localhost. يلزم HTTPS وCookie آمن ونطاقات CORS/Sanctum دقيقة في بيئة النشر.
3. **إدارة أسرار Super Admin:** الأوامر الإدارية متاحة محليًا؛ يجب حصر صلاحيات حساب النظام ومراجعة آلية تشغيلها وتسجيلها عند إعداد بيئة النشر.
4. **اختيار المصادقة:** التنفيذ مصمم لـSPA على أصل موثوق باستخدام Cookies. إذا تغير نشر الواجهة إلى أصل مستقل أو ظهرت حاجة لتطبيقات طرف ثالث، يجب مراجعة نموذج المصادقة قبل إصدار tokens.
5. **مقياس التنفيذ:** اختُبرت صحة السلوك فقط، لا الأداء تحت حمل؛ يجب وضع حدود الصفحات ومراقبة الاستعلامات في المرحلة التي تضيف واجهات البيانات، ثم إجراء اختبار حمل في بيئة مناسبة.
6. **تكامل البيانات:** اتصال التطوير وفحص الصحة وتدفق CSRF يعملان عبر proxy. رفع Excel وتحليل الشحنات لا يزالان محليين في IndexedDB؛ لا يوجد حتى الآن endpoint لاستيراد/مزامنة ملفات أو سجلات الشحنات، لذلك لم يتغير تدفق البيانات الحالي. يلزم تنفيذ عقد الاستيراد وربطه في مرحلة لاحقة.
