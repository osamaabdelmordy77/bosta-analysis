# تقرير تخزين الاستيراد في MySQL

**التاريخ:** 2026-11-03
**النطاق:** إلغاء التخزين التشغيلي في IndexedDB، وتوصيل استيراد ملفات Excel بقاعدة MySQL.
**الحالة:** التنفيذ والاختبارات المحلية مكتملة؛ نقل بيانات المتصفح القديمة ينتظر أول تسجيل دخول من المتصفح الذي يحتويها.

## القرارات المعمارية

- قاعدة MySQL هي مصدر الحقيقة الوحيد للملفات والصفوف والإعدادات. لا تُكتب ملفات الرفع الجديدة أو سجلاتها إلى IndexedDB.
- يحلل React المصنف خارج الخيط الرئيسي عبر Web Worker عند توفره. يرسل الملف الأصلي إلى Laravel ويحفظه في `import_file_contents.contents` بنوع MySQL `LONGBLOB` مع SHA-256.
- تُرسل كل ورقة في دفعات لا تتجاوز 200 صف من الواجهة. يقبل Laravel حتى 500 صف لكل طلب؛ التنفيذ المحلي متزامن ولا يحتاج Queue Worker أو Redis أو Horizon.
- تحفظ بيانات كل صف المصدر كاملة في `import_source_rows.source_values` مع رقم الورقة والصف والعناوين الأصلية. يغطي Manifest التشغيل 211 عمودًا؛ وتبقى القيم المصدرية متاحة حتى عندما لا يمكن تحويل قيمة إلى نوع العمود المؤقت.
- تحفظ اللقطات المهيكلة والعلاقات المالية والخدمية والجغرافية ومحاولات التسليم، مع مراجعات استيراد قابلة للتتبع وسجلات تدقيق.
- يمنع مفتاح بصمة التتبع المكرر إنشاء أكثر من لقطة للشحنة نفسها داخل تشغيل واحد؛ يحتفظ النظام بصف المصدر الثاني ويعلّمه كتكرار. يسمح بظهور رقم التتبع في تشغيل/تاريخ آخر كتاريخ تشغيلي مستقل.
- حذف ملف من الشاشة يعني أرشفته وإخفاءه من العرض النشط؛ تبقى المصنفات والصفوف والمراجعات وسجلات التدقيق في MySQL.
- تخزن إعدادات أساس المركز وتجاوزات الأعمدة في MySQL على مستوى المؤسسة.

## نقل IndexedDB القديمة

أزيلت واجهات القراءة والكتابة التشغيلية القديمة وملف الخدمة `src/services/db.ts`. بقي قارئ انتقال واحد لقاعدة `LogisticsAnalyticsDB` كي يفي باختيار المستخدم «انقل ثم امسح»:

1. يبدأ النقل بعد تسجيل دخول مستخدم مرتبط بمؤسسة.
2. يقرأ بيانات الملفات والإعدادات، ثم يجلب سجلات كل ملف بمؤشر `fileId` على دفعات من 500 سجل كحد أقصى.
3. يستخدم مفتاحًا ثابتًا لكل ملف/صف لسلامة إعادة المحاولة، ويتحقق من عدد صفوف MySQL مقابل العدد المقروء من المتصفح.
4. يقارن مجموع صفوف الملفات بعدد صفوف مخزن المتصفح. إذا اختلفت الأعداد أو فشل الرفع، تبقى قاعدة IndexedDB دون حذف.
5. بعد نجاح التحقق فقط، يغلق الاتصال ويحذف قاعدة المتصفح. إذا كانت هناك نافذة قديمة تمنع الحذف، تظهر رسالة تطلب إغلاقها ويظل النقل قابلًا لإعادة المحاولة.

قاعدة التطبيق القديمة لا تحتوي مصنف Excel الأصلي ولا الأعمدة الـ211 الخام؛ مخزنها يحتوي ملخصات الشحنات وبعض الإعدادات وبيانات الملفات. لذلك ينقل المسار المتبقي الملخصات القابلة للاسترجاع فقط. أي رفع جديد يحفظ المصنف الأصلي وكل صف/قيمة مصدرية في MySQL. لا يمكن استعادة الخلايا القديمة التي لم يحتفظ بها التطبيق.

قاعدة بيانات المتصفح مقيدة بالـorigin والمتصفح والجهاز. لم يمكن تنفيذ حذف فعلي من جلسة المتصفح أثناء هذا التشغيل؛ أول تسجيل دخول عبر `http://localhost:3000` هو الذي ينفذ النقل والتحقق والحذف تلقائيًا. لا يسجل التقرير النقل القديم على أنه مكتمل قبل ذلك.

## تجهيز التطوير المحلي

- المؤسسة: `bosta-local`، والعضو الأول `local.admin@bosta.test` بدور Organization Admin. كلمة المرور المؤقتة أُنشئت عشوائيًا وسلمت لصاحب المشروع خارج هذا التقرير.
- قاعدة التطوير النشطة: `bosta_analysis_local` على MariaDB 10.4.28 المرفق بـXAMPP عبر `127.0.0.1:3306`؛ قاعدة الاختبار: `bosta_analysis_test` على الخادم نفسه. إعداد التطوير يستخدم حساب `root` بلا كلمة مرور بطلب المستخدم. خادم MySQL 8 السابق على 3307 وقاعدته محفوظان دون تعديل.
- الواجهة: Vite على المنفذ 3000؛ Laravel على 8000؛ Vite proxy يمرر API وSanctum وفحص الصحة إلى Laravel.
- PHP المحلي يعلن `upload_max_filesize=40M` و`post_max_size=40M`. حد Laravel للملف 32 MiB. لم تشغّل Queue أو Redis/Horizon أو Containers.

## نتائج التحقق

- جميع migrations من 1 إلى 10 مطبقة على MySQL التطوير، بما فيها LONGBLOB وجداول الاستيراد القديم.
- اختبار تدفق الاستيراد على قاعدة الاختبار: تخزين بايتات المصنف ومطابقة SHA-256، حفظ 211 قيمة صف مصدرية، وسم التكرار دون إسقاط صف المصدر، إعادة طلب الدفعة بأمان، نشر السجل، قراءته من مسار التقرير، والتعرف على إعادة رفع المصنف نفسه. النتيجة: **23 assertion ناجحة**.
- في أول تشغيل للاختبار ظهر تعارض عند وجود تكرار داخل الدفعة نفسها لأن اللقطات لم تكن قد كُتبت بعد. أضيف كشف محلي للتكرار داخل الدفعة مع إبقاء قفل التشغيل والمعاملة، ثم اجتاز الاختبار كاملًا.
- اختبار انتقال الملخصات القديمة وإعادة المحاولة والتحقق قبل الإكمال: **15 assertion ناجحة**. كشف الاختبار أيضًا حقلًا خامًا مفقودًا في استعلام قراءة الملخصات القديمة، وتم إصلاحه.
- مجموعة Laravel كاملة: **38 اختبارًا و233 assertion ناجحة**.
- TypeScript (`npm run lint`) وبناء Vite (`npm run build`) نجحا.
- فحص HTTP عبر Vite: الصفحة `/` وLaravel `/up` رجعا 200، CSRF رجع 204، وتسجيل الدخول واسترجاع المؤسسة والخروج نجحت.
- لم يُرفع المصنف الأصلي للاختبار ولم يُعدّل.
- اختُبر توافق migrations العشر واختبارات Laravel على MariaDB 10.4.28 في XAMPP؛ النتيجة **38 اختبارًا و233 assertion ناجحة**. نجاح اختبار API عبر واجهة Vite أكد أن خادم Laravel النشط قرأ إعداد 3306.

## قيود العمل المتبقية

- يلزم تسجيل الدخول من المتصفح الذي يملك IndexedDB القديمة لإكمال النقل وحذف المخزن فعليًا والتحقق منه.
- التحليلات الحالية ما زالت تجلب الصفحات إلى ذاكرة React لحساب التجميعات في المتصفح؛ الاستعلامات نفسها cursor-paginated، لكن تجميعًا server-side أو cache محسوبًا يحتاج عملًا لاحقًا إذا كبر حجم البيانات.
- التحويل إلى قيم الأنواع المنظمة مؤقت حتى اعتماد قواعد الأعمال ومراجعة عينات Excel متنوعة؛ تظل قيم المصدر كاملة محفوظة.
- التحميل الإنتاجي لم يُختبر ولم تُشغل اختبارات حمل.
